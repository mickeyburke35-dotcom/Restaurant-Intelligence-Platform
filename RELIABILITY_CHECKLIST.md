# Reliability Checklist

Feature: Review Insight Generation

Source of truth: `PRD.md`, `AI_BEHAVIOUR.md`, `AGENT_BLUEPRINT.md`, `ARCHITECTURE.md`, and `prisma/schema.prisma`.

| Possible hallucination or AI failure | Impact level | Mitigation strategy | Human-review point |
| --- | --- | --- | --- |
| Invented review statistic, such as a fabricated percentage, review count, average rating movement, or theme frequency. | High | Compute counts, ratings, date windows, and theme frequencies outside the model from tenant-scoped review records. Pass only calculated values and source review IDs into the prompt. Reject generated claims that do not match deterministic counts. | Manager or Analyst reviews the draft insight before status can move from `NEEDS_REVIEW` or `DRAFT` to `APPROVED`. |
| Unsupported competitor claim, such as saying a competitor is outperforming the restaurant without a linked competitor observation. | High | Allow competitor comparisons only when selected `CompetitorObservation` records include source URL, observed date, and agency-scoped competitor ID. If evidence is missing, label the claim as insufficient evidence. | Human reviewer checks competitor evidence before any `COMPETITOR_COMPARISON` or high-impact recommendation appears in a client-facing report. |
| Wrong sentiment classification for a review, theme, or insight. | Medium | Store sentiment separately from raw reviews, show confidence level, and keep the review excerpt visible beside the draft insight. Use review ratings and text as supporting signals, but do not let either override human judgment. | Analyst reviews sentiment on the insight detail screen and either approves, edits, or rejects the draft. |
| Insight not linked to source reviews. | High | Require every insight claim to create `InsightSourceReview` rows with `review_id`, `agency_id`, optional relevance score, and evidence excerpt. Block approval when `sourceReviewCount` is zero for evidence-dependent insight types. | Approval control remains disabled or blocked until the reviewer sees at least one source review reference. |
| Broken JSON, malformed output, missing fields, or format drift from the model response. | Medium | Validate model output against a strict schema before saving. Reject responses missing title, summary, sentiment, confidence, model, timestamp, status, or source references. Retry with a repair prompt only using the same evidence payload. | Reviewer never sees invalid model output as a finished insight; invalid attempts are logged for analysis. |
| Low-confidence insight treated as approved or included in a report without review. | High | Default generated insights to `NEEDS_REVIEW`. Store `confidence` and `confidenceLevel`; require explicit reviewer action for `LOW` confidence or `highImpact` insights. Default reports to approved insights only. | Manager must approve low-confidence or high-impact insights before report export includes them. |
| Cross-tenant data leakage in prompt input, generated output, source links, report export, or audit trail. | Critical | Resolve active `agency_id` and role before each query, job, AI prompt, and export. Use tenant-aware Prisma filters and composite relations that include `agency_id`. Add tests proving Agency A cannot read, infer, export, or prompt with Agency B data. | Owner/Admin reviews audit logs for insight generation and report export; any tenant mismatch blocks release. |
| Prompt injection from review text or competitor notes changes model behavior. | High | Treat reviews and competitor notes as untrusted evidence. Wrap source text as data, not instructions. The system prompt must restate tenant, source, compliance, and evidence-only rules. | Reviewer checks whether the summary follows project AI rules and ignores reviewer-text instructions. |
| Sparse, stale, or conflicting evidence presented as a firm recommendation. | Medium | Include review count, date range, source coverage, observed dates, and confidence. Require the model to say when evidence is insufficient or mixed. | Human reviewer confirms the insight wording does not overstate sparse or stale evidence. |
| Source approval or compliance status ignored during review import or insight generation. | High | Generate insights only from approved public reviews, partner exports, CSV imports, manual demo data, or permitted API sources with `APPROVED` source status. Exclude rejected or pending sources from the prompt. | Manager verifies source coverage and approval status before generating insights for a client deliverable. |
| Report narrative includes rejected, archived, draft, or unreviewed insights. | High | Report export should default to `approvedOnly` and tenant-scoped filters. Exclude `REJECTED`, `ARCHIVED`, and unapproved insight statuses unless an internal draft export is clearly labeled. | Manager reviews report preview and confirms included insights are approved for the selected client, location, and date range. |
| Model omits timestamp, model name, prompt version, or confidence metadata. | Medium | Require metadata fields before saving an `Insight`. Log generation attempts with model and prompt version for traceability. | Reviewer checks model metadata in the insight detail before approval. |
